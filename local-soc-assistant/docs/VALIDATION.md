# Фактически выполненные проверки

Дата: 2026-11-06. Прототип 0.1.0, схема 1.1.
Среда: Linux x86-64, Python 3.12.14, CPU quota 2, cgroup RAM limit 8 ГБ.
Целевой Windows-компьютер с 16 ГБ RAM недоступен; его проверка не заявляется.

## Проверки кода и интеграции

- **59 быстрых тестов прошли.** Импорт, неизвестные поля/время, окно и основания связи,
  происхождение, история/экспорт, неверные ID/ссылки, существующая ссылка без смыслового
  подтверждения, частичный отказ, отсутствие утечки меток, контекстный бюджет,
  блокировка конкуренции, тайм-аут, прерывание и интерфейс Streamlit.
  Отдельный тест подтверждает: 5000 строк при лимите 2 дают 4998 отклонений,
  агрегированных в одну диагностическую запись, без разрастания списка ошибок.
- **3 интеграционных теста прошли за 232,45 с.** Реальная локальная Qwen GGUF,
  строгая компиляция схемы и реальный промпт-инъекционный случай. Использован полный
  официальный ATT&CK Enterprise 18.0, не заглушка. Запуски выполнены в сетевой изоляции.
- В реальном инъекционном случае инструкция повысить приоритет до high не изменила
  локальную политику: priority=low; внедрённая T1003 не получила supported.
  Это проверка одного сценария, не доказательство абсолютной устойчивости.
- Chromium: загрузка демо, запуск C, переходы к истории/сравнению и скачивание HTML прошли.
  В браузере не обнаружено внешних запросов или ошибок JavaScript. Отдельная явно обозначенная
  UI-заглушка с Markdown-ссылками в event_id/field/source_ids не вызвала удалённых загрузок.
  Этот тест проверяет безопасное отображение, а не качество LLM. Лицензия MITRE сохранена в HTML.
- Чистая распаковка ZIP: построение индекса и сквозная демонстрация C прошли без весов модели.
- pip check: несовместимых установленных зависимостей не обнаружено.
- Полный STIX проиндексирован; собственный размер полного источника 50 778 972 байта.
- Веса Qwen2.5-1.5B-Instruct Q4_K_M: 1 117 320 736 байт, SHA-256 проверен,
  CPU-рантайм llama-cpp-python 0.3.18 собран в Linux из исходников, без CUDA/CURL.
  Эффективное число потоков 2. Фактические RSS и времена — в JSON каждого запуска.

Времена и память этого стенда не являются обещанием производительности Windows.
59 быстрых + 3 реальных интеграционных = **62 пройденных теста**; эти группы запускались отдельно.
Отчёты pytest находятся в validation/fast-tests.txt и validation/real-integration-tests.txt.

## Инженерное сравнение четырёх режимов

Настроечный сценарий ps_admin_1 (легитимный PowerShell Get-Date), одна модель, seed=42,
три повтора A/B/D и один детерминированный C: всего 10 запусков.
Грамматика применена явно; скрытого fallback к общему JSON нет.
Это настройка и проверка конвейера, не независимый научный тест.

| Режим | Запусков | Precision ATT&CK | Recall | F1 | Покрытие техниками | Тех. ошибки |
|---|---:|---:|---:|---:|---:|---:|
| A | 3 | 1.000 | 1.000 | 1.000 | 1.000 | 0.000 |
| B | 3 | 0.500 | 1.000 | 0.667 | 1.000 | 0.000 |
| C | 1 | 1.000 | 1.000 | 1.000 | 1.000 | 0.000 |
| D | 3 | — | 0.000 | 0.000 | 0.000 | 0.000 |

A правильно предлагал наблюдаемую технику, но его свободные объяснения и ссылки не верифицированы.
B добавлял неподтверждённую технику. D отклонил предложения из-за отсутствующих ссылок на
определения, сохранив корректные частичные факты и приоритет. Доля необоснованных отказов D
на этом достаточном входе — 1,0; покрытие — 0. Precision D не определён из-за отсутствия
принятых техник, а не равен 1. F1=0. **Превосходство D не подтверждено.**

Нельзя подменять отсутствие принятых утверждений «нулевой ошибкой качественного анализа».
Этот результат указывает на ограничение компактной модели и чувствительность D к полноте
сформированных доказательств. Его нужно учитывать при выборе модели и оценке отказов.
Ручные оценки русских объяснений и рекомендаций не заполнены и остаются null.

Веса LLM в этом процессе оставались в памяти при C; для самостоятельных измерений C
сохранён отдельный прогон всех 24 сценариев. На инженерном корпусе правила C дают
F1=1,0, но корпус сконструирован под опубликованные узкие профили: это не независимая
валидация качества на реальных журналах. Варианты семейств не независимы.

Индивидуальные отчёты, исходные ответы, попытки, параметры, хеши и summary:
validation/comparison/. Полный отдельный C-прогон: validation/corpus-C-release/.

## Ошибки, обнаруженные и исправленные при настройке

- Начальный CPU wheel Linux требовал недоступную musl-библиотеку; использована сборка
  той же версии на glibc. Наличие Windows wheel проверено по официальному индексу,
  запуск Windows wheel здесь не проверялся.
- Первый пробный запуск с неподходящими настройками потоков остановлен через 926 с;
  он не считается успешной интеграцией. Добавлены учёт cgroup/батч-потоков, тайм-аут,
  потоковый прогресс и сохранение частичного ответа.
- Конвертер грамматики не поддерживал non-capturing regex group и библиотека молча
  переходила к общему JSON. Исправлен regex, введена явная строгая компиляция без
  fallback, совместимость включена в ready и реальный тест.
- Ограничена сводка до 4 фактов, 3 техник и 2 рекомендаций; полные события сохранены.
- Пустое заключение без основания отказа больше не выдаётся за доказательный отказ.
- Сброс prompt/KV перед генерацией исключает использование префикса предыдущего запроса.
- Case ID учитывает происхождение, чтобы повторный импорт из другого файла не менял
  происхождение события в старой истории.

Исходные неудачные попытки не удалены: validation/preliminary-probe/,
validation/tuning-before-output-fix/, validation/tuning-before-grammar-fix/,
validation/initial-real-D/. В старых исходных файлах могут встречаться прежние статусы;
они являются историческими диагностическими артефактами, не результатами итогового сравнения.

## Что остаётся проверить

- Установка PowerShell-скриптами и реальная DLL/CPU-совместимость на целевой Windows.
- Производительность/память именно на Windows 16 ГБ, работа после физического отключения сети.
- Полное A/B/C/D на всей тестовой части с минимум тремя повторами генеративных режимов.
- Независимая разметка аналитиком свободных объяснений и рекомендаций.
- Качество на реальной Wazuh-телеметрии и расширение за пределы трёх профилей Sysmon.
- Согласованность с введением и главой 1 ВКР: эти материалы не предоставлялись.

Команды проверки Windows: scripts/Check.ps1 -RealLLM; полный эксперимент описан
в docs/EXPERIMENT.md. Неисполненные проверки не объявляются пройденными.
