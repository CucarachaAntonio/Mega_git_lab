# Верификация и границы смысловой проверки

Достоверность ссылки, смысловая достаточность и истинность гипотезы разделены.
Верификатор не вызывает модель и не использует самооценку уверенности.

## Обязательные признаки

Все три профиля требуют `data.win.system.eventID` = 1 / "1" и
`data.win.system.providerName` = `Microsoft-Windows-Sysmon`.
Поля image и commandLine должны относиться к одному событию, а в ответе должны
быть приведены точные ссылки на все четыре обязательных поля.

| Техника | image (basename, без учёта регистра) | Командная строка | Дополнительные сведения |
|---|---|---|---|
| T1059.001 | powershell.exe | Содержит имя powershell с границами | ParentImage, User и согласованные работы полезны, но их отсутствие не доказывает атаку |
| T1059.003 | cmd.exe | Содержит имя cmd с границами | Родительский процесс, контекст пользователя |
| T1053.005 | schtasks.exe | Содержит schtasks и аргумент /create | Task Scheduler registration events нужны для вывода об успешном создании |

Текущий профиль schtasks поддерживает попытку создания задачи этим инструментом.
Он не покрывает COM/API, XML, GUI или PowerShell cmdlets планировщика.
Powershell Core/pwsh и Security 4688 намеренно вне этих узких профилей.
Наличие исполняемого имени в аргументе само по себе не доказывает запуск: дополнительно обязателен image.
Даже корректные поля могут быть ошибкой/подделкой датчика; прототип не проверяет доверенность агента.

## Проверки

1. Pydantic проверяет общую схему. Ошибка схемы — технический результат после максимум одной попытки исправления.
2. Существование ATT&CK ID и active-статус в конкретном снимке.
3. Наличие event_id, поля и точное совпадение значения с сохранённым представлением.
4. Существование chunk_id среди результатов текущего поиска и соответствие определению техники.
5. Полнота процитированных признаков одного события; противоречия image/commandLine/профилю.
6. Для поддержанных профилей свободное rationale заменяется каноническим ограниченным объяснением.
7. Рекомендации D заменяются безопасными шаблонами с проверенными ссылками.

Факт имеет форму event_id/field/value, без свободного текста, который мог бы скрывать неподтверждённую
интерпретацию. Гипотезы остаются отдельно и явно не считаются верифицированными.
Содержательная правильность произвольных гипотез и рекомендаций в A/B требует аналитика.
Для остальных ATT&CK техник используется `analyst_required`, даже если ссылки существуют.

## Статусы

- `supported`: все условия узкого профиля выполнены; не равно «атака доказана».
- `rejected`: конкретный вывод недопустим, сохранены код, основание и необходимые данные.
- `analyst_required`: содержательная проверка не выполнена.
- `unchecked`: режим A/B/C не выполнял постпроверку D.

`unknown_attack_id`, `inactive_attack_id`, `invalid_event`, `invalid_field`,
`content_mismatch`, `invalid_source`, `source_mismatch`, `insufficient_evidence`, `contradiction`
различаются в отчёте. Технические сбои хранятся в errors, а не выдаются за отказы.
Сохраняются исходный ответ и итоговый результат; принятые частичные факты не удаляются из-за отказа от другой гипотезы.
Утверждения «успешное закрепление», «кража данных» и «злонамеренность» этими профилями не подтверждаются.

Дополнительные признаки профилей: parentImage и user. Их наличие/неизвестность фиксируются
отдельными `optional_context` проверками, не подменяют обязательные признаки и не увеличивают «уверенность».
Рекомендации D получают ссылки на поддержанные техники/определения, связанные с теми же событиями.
Это локальные условные инструкции проверки, а не объявление их официальными мерами MITRE
и не доказательство эффективности реагирования. Общие рекомендации сбора контекста возможны
даже при отклонении техники; в таком случае technique_ids/source_ids могут быть пустыми.

Пустое заключение модели без причины не считается доказательным отказом: `missing_conclusion`,
статус partial, нулевое покрытие. Самостоятельные текстовые отказы модели помечаются
`model_declared_not_semantically_verified`; они не приравниваются к проверенным отказам
по конкретному нарушенному условию. Их обоснованность входит в независимую оценку/разметку.
