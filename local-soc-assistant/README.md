# Локальный интеллектуальный ассистент ИБ

Учебно-исследовательский прототип для ВКР по специальности 10.05.02.
Импортирует файловые предупреждения Wazuh, объединяет события в случаи, использует
локальные MITRE ATT&CK и LLM, проверяет доказательства и сохраняет отчёты.
Интерфейс на русском, SQLite/FTS5, один пользователь, сервер `127.0.0.1:8501`.
Ассистент только рекомендует; исполнительных инструментов нет.

## Быстрый запуск на Windows

Требуется **Windows x64 и Python 3.12 x64** с `py` launcher. Docker, WSL, CUDA и платные API не нужны.
Распакуйте архив в обычную доступную для записи папку. В PowerShell из этой папки:

```powershell
# Полная установка: зависимости, CPU-рантайм, GGUF (~1.12 GB), индекс.
powershell -ExecutionPolicy Bypass -File .\scripts\Setup.ps1 -FullAttack

# Проверка и запуск:
.\scripts\Check.ps1 -RealLLM
.\scripts\Start.ps1
```

Откройте `http://127.0.0.1:8501`. На вкладке импорта нажмите
«Загрузить демонстрационный случай», затем на вкладке анализа выберите режим.
Установка требует интернет. После подготовки отключите сеть и повторите анализ.
Никаких скачиваний в процессе анализа нет.

Быстрая демонстрация **без модели**, только правила и настоящий локальный RAG:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Setup.ps1 -DemoOnly
.\scripts\Start.ps1
```

Это режим C, не имитация работы LLM. Для A/B/D нужна полная подготовка.
Скрипты не меняют системную ExecutionPolicy и не требуют постоянных прав администратора.
Если конкретная среда запрещает запуск скриптов, используйте эквивалентные команды из [WINDOWS.md](docs/WINDOWS.md).

## Что реализовано

- JSON/JSONL Wazuh, ограничения размера, глубины, длины полей и количества записей;
  принятые/отклонённые строки, причины, дубликаты и исходные файлы для аудита.
- Нормализация и SHA-256 происхождения; неизвестное время и часовой пояс не выдумываются.
- Связывание по одному узлу и общей учётной записи/процессу в настраиваемом окне.
  Окно ограничивает весь случай, а не только соседние события. Один IP не связывает события.
- Версионированный ATT&CK, FTS5/BM25, запросы, оценки и версии индекса.
- Реальная CPU-генерация через llama-cpp-python с JSON schema, лимитом контекста
  и максимум одной повторной попыткой исправления формата.
- Четыре режима A/B/C/D, отдельная доказательная проверка и частичные отказы.
- Приоритет очередности проверки по общей явной политике, независимо от уверенности LLM.
- История, состав случаев, переходы к доказательствам, сравнение запусков, JSON/HTML.
- 24 синтетических сценария в 12 семействах, эталоны отдельно, CLI эксперимента и форма разметки аналитиком.
- Быстрые тесты с обозначенной заглушкой и отдельный интеграционный тест с реальной моделью.

## Режимы

| Режим | Генерация | RAG | Доказательная постпроверка |
|---|---|---|---|
| A | LLM | Нет | Нет, только формат |
| B | Та же LLM | Да | Нет, только формат |
| C | Фиксированные правила | Да | Нет механизма D |
| D | Та же LLM | Тот же поиск | Да, ссылки, значения, профили и отказ |

Общие этапы: импорт, нормализация, связывание, представление входа, политика приоритета,
схема результата, сохранение и независимый оценщик. Приоритет общий для чистоты сравнения
ATT&CK/доказательств; его равенство между режимами ожидаемо и **не подтверждает пользу D**.
Правила C используют те же опубликованные узкие признаки для генерации кандидатов,
но не проверяют произвольные утверждения модели. В A/B механизм D скрыто не включается.

## Конфигурация и знания

Все пути и ресурсные пределы находятся в `config.toml`. По умолчанию: одна LLM,
CPU (`n_gpu_layers=0`), 4 потока, контекст 4096, ответ до 1100 токенов, до 4 RAG-фрагментов.
При превышении контекста возвращается техническая ошибка с предложением уменьшить случай,
а не скрыто обрезанные события. RAG-фрагменты могут исключаться по бюджету токенов: полная выдача и перечень исключений сохраняются. Модель освобождается после отдельного интерактивного запуска;
эксперимент переиспользует один экземпляр, загрузка измеряется отдельно. Перед каждой генерацией сбрасывается состояние prompt/KV, чтобы не смешивать эффект повторного использования префикса со скоростью режимов.

Исходная модель: **Qwen2.5-1.5B-Instruct-GGUF Q4_K_M**, Apache-2.0,
фиксированная ревизия и SHA-256 в `soc_assistant/prepare.py` и манифесте модели.
Размер файла не равен потреблению RAM. Фактические время и память зависят от машины.
Другую модель можно подключить путём в конфигурации; нужен GGUF с поддерживаемым chat template.

Полный официальный `knowledge/enterprise-full.json` получается скриптом `Setup.ps1 -FullAttack` с проверкой SHA-256. Он не хранится в Git. По умолчанию для короткой демонстрации используется **демонстрационная выборка из официального ATT&CK Enterprise 18.0**:
три поддерживаемых техники, T1003 для проверки неподдерживаемого профиля,
сопутствующий объект и три исторических описания процедур. Это не полный Enterprise-снимок.
Происхождение и хеш полного исходника — `knowledge/manifest.json`.

Для полного снимка используйте `Setup.ps1 -FullAttack` либо:

```powershell
.\.venv\Scripts\python.exe -m soc_assistant.cli prepare --attack
# Измените paths.snapshot на knowledge/enterprise-full.json в config.toml.
.\.venv\Scripts\python.exe -m soc_assistant.cli prepare --index
```

Индекс пересоздаётся также после изменения инструкции или размера фрагмента.
При несоответствии конфигурации/снимка анализ блокируется. Обновление — отдельная операция.
Сходные исторические описания используются как контекст, не как доказательства текущего случая.

## CLI

Запускайте команды из корня проекта. Глобальный `--config PATH` ставится перед подкомандой.

```powershell
$PythonExe = ".\.venv\Scripts\python.exe"
& $PythonExe -m soc_assistant.cli ready --require-llm
& $PythonExe -m soc_assistant.cli import examples\invalid.jsonl
& $PythonExe -m soc_assistant.cli demo --mode C --out data\demo-C
& $PythonExe -m soc_assistant.cli analyze examples\demo.jsonl --mode D --out data\demo-D
& $PythonExe -m soc_assistant.cli experiment --modes A B C D --repeats 3 --split test --out data\experiment
```

`import` возвращает код 3 при ошибках записей, но сохраняет принятые события.
`analyze` явно показывает число ошибок импорта и анализирует выбранный случай (`--case-index`).
Код 2 означает техническую ошибку анализа/неготовность. Отказ по доказательствам не равен сбою.
`experiment` сохраняет все отдельные отчёты, план, метрики и `analyst-review.csv`.
При длительных экспериментах отдельные результаты пишутся по мере выполнения.

## Данные, ограничения и проверки

Файловый Wazuh выбран, чтобы работать без действующего SOC. Suricata и живая интеграция
оставлены расширениями. Синтетические файлы имеют форму предупреждений Wazuh, но не являются
настоящими предупреждениями продукта или реальной телеметрией OTRF. OTRF не использовался.
Скрытые метки и Wazuh `rule.mitre` отсутствуют во входе анализатора; исходники доступны только для аудита.
Не размещайте чувствительные файлы в git: `data/`, `models/` исключены.

Содержательно проверяются только узкие профили **Sysmon Process Create (eventID=1)**:
T1059.001, T1059.003, T1053.005. Для других техник явно требуется аналитик.
Успешное создание задачи, закрепление и злонамеренность этими профилями не доказываются.
События других провайдеров могут импортироваться, но не получают автоматическую семантическую проверку.

Материалы ВКР (введение и глава 1) не предоставлялись; согласованность с ними не заявляется.
Статус выполненных и невыполненных проверок см. [VALIDATION.md](docs/VALIDATION.md).

## Фактический статус поставки

Проверены 59 быстрых и 3 реальных интеграционных теста на Linux, полный ATT&CK и один
реальный инъекционный сценарий. Проведён инженерный A/B/C/D-прогон одного настроечного случая
с тремя повторами LLM; в нём D избыточно отказывал из-за отсутствующих ссылок.
Windows, полный тестовый эксперимент и ручная разметка не объявляются проверенными.
Подробности и все ограничения: docs/VALIDATION.md.

Версия для GitHub содержит исходный код, небольшой официальный демонстрационный снимок
и сохранённые результаты проверок. Полный ATT&CK, GGUF, индексы и окружение восстанавливаются
командами установки и не входят в Git.
